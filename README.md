# TaskFlow

Офлайн-приложение на Flutter для управления проектами и задачами. Все данные
хранятся в SQLite через Drift и остаются доступными после перезапуска.

## Запуск

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # только после изменения таблиц
flutter run
flutter test
```

После первого запуска откройте **Инструменты** (значок ключа) и нажмите
**Демо-данные**: появятся 3 пользователя, 2 проекта и 5 задач. Там же есть
набор на 10 000 задач, очистка базы и сравнение скорости запросов.

От имени текущего пользователя меняются статусы и пишутся комментарии. Выбрать
его можно кружком в правом верхнем углу.

## Архитектура

```
Presentation (виджеты)     lib/presentation/
  → State Management       lib/state/          Cubit, подписки на watch()
    → Repository           lib/repositories/   правила, транзакции, запросы
      → Database           lib/database/       таблицы, миграция (Drift)
Model                      lib/models/         классы данных, enum, фильтры
```

В виджетах и Cubit нет SQL: вся работа с базой идёт через репозитории.
Проверки также стоят в репозиториях, поэтому их нельзя обойти с другого экрана.

## База данных

```
users ──< project_members >── projects ──< tasks ──< comments
  │                                         ├────< attachments
  └── исполнитель, автор, инициатор ────────┴────< task_history
```

| Таблица | Назначение | Ключевые ограничения |
|---|---|---|
| `users` | пользователи | `email` UNIQUE, хранится в нижнем регистре |
| `projects` | проекты | CHECK на статус |
| `project_members` | связь Many-to-Many, роль | PK (`project_id`, `user_id`), каскад |
| `tasks` | задачи | `project_id` NOT NULL, FK с каскадом; CHECK на статус и приоритет; `deleted_at` для корзины |
| `comments` | комментарии | каскад от задачи, автор SET NULL |
| `attachments` | вложения | только путь к файлу, не содержимое |
| `task_history` | история | каскад от задачи, пользователь SET NULL |
| `app_settings` | текущий пользователь | дополнительная таблица |

Внешние ключи включаются командой `PRAGMA foreign_keys = ON` при каждом
открытии базы: по умолчанию SQLite их не проверяет.

## Принятые решения

Задание оставляет эти вопросы открытыми, поэтому решения описаны здесь.

- **Незавершённая задача:** статус `todo` или `inProgress`. Отменённые задачи
  считаются отдельно.
- **Процент выполнения проекта:** завершённые задачи делятся на все, кроме
  отменённых и удалённых. Проект без задач показывает 0 %.
- **Просроченная задача:** незавершённая, дедлайн раньше сегодняшнего дня. Дедлайн
  хранится как дата, поэтому в сам день дедлайна задача ещё не просрочена.
- **Лимит трёх задач** проверяется при создании, смене исполнителя и переносе
  дедлайна. Восстановление из корзины и возврат статуса в работу новым
  назначением не считаются, поэтому в этих случаях задач на дату может стать
  больше трёх.
- **Undo** отменяет только последнее изменение статуса. Отмена сама попадает
  в историю, повторно отменить её нельзя.
- **Участника нельзя убрать из проекта**, пока у него есть незавершённые задачи
  этого проекта. Иначе исполнитель оказался бы не из проекта. В проекте также
  всегда остаётся хотя бы один Owner.
- **После удаления пользователя** завершённые задачи, история и комментарии
  остаются, вместо имени показывается «Удалённый пользователь» или «Без
  исполнителя».
- **Поиск** идёт по отдельному полю `search_text` в нижнем регистре: `LIKE`
  и `lower()` в SQLite не приводят кириллицу к одному регистру.
- **Вложения** копируются в папку приложения, потому что файл из системного
  диалога выбора может исчезнуть из временного кэша.

## Производительность

Набор: 1 000 пользователей, 100 проектов, 10 000 задач. Каждый запрос выполнялся
20 раз, в таблице среднее время в миллисекундах.

| Запрос | Windows, с индексом | Windows, без | Эмулятор, с индексом | Эмулятор, без |
|---|---:|---:|---:|---:|
| Список, новые сверху | 0,16 | 1,09 | 1,39 | 8,00 |
| Пагинация, OFFSET 5000 | 0,33 | 2,12 | 1,75 | 5,00 |
| Сортировка по дедлайну | 0,16 | 1,35 | 1,65 | 4,28 |
| Фильтр по статусу | 0,12 | 1,31 | 1,69 | 3,65 |
| Фильтр по приоритету | 0,14 | 1,32 | 1,64 | 4,70 |
| Задачи проекта | 0,14 | 0,95 | 3,58 | 3,54 |
| Лимит 3 задачи на дату | 0,10 | 0,67 | 2,44 | 3,45 |
| Просроченные задачи | 0,51 | 1,21 | 2,47 | 4,62 |
| Поиск по тексту | 2,30 | 2,26 | 6,26 | 5,53 |

Выводы:

- На Windows индексы ускорили запросы примерно в 2,4–11 раз. На эмуляторе разница
  меньше: там база работает в отдельном isolate, и передача данных, вероятно,
  занимает заметную часть времени. Отдельные замеры на эмуляторе сильно
  колеблются, поэтому один запуск не стоит считать точным значением.
- Поиск индекс не ускоряет: подстроку в середине текста обычный индекс найти не
  может. На 10 000 задач это единицы миллисекунд, для заметно большего объёма
  понадобился бы полнотекстовый индекс FTS5.
- Индекс не всегда помогает сам по себе. В первой версии сортировка по дедлайну
  с индексами работала медленнее, чем без них (3,8 мс против 2,0). Помогли
  составные индексы под реальные запросы и `LEFT JOIN projects`, который заставляет
  SQLite читать сначала таблицу `tasks`. План запроса проверяет
  `test/performance_test.dart`.

Свои цифры можно получить на экране «Инструменты → Сравнить скорость запросов».
Замер идёт на временной базе, рабочие данные не меняются.

## Тесты

119 тестов работают с настоящим SQLite в памяти, база не подменяется моками.

| Файл | Что проверяет |
|---|---|
| `users_test.dart` | создание, удаление, уникальность email |
| `projects_test.dart` | проекты, участники, роли, каскадное удаление |
| `tasks_test.dart` | создание, проверка исполнителя, транзакции, история, Undo, лимит, корзина, фильтры, поиск, пагинация, `watch()` |
| `comments_attachments_test.dart` | комментарии и вложения |
| `stats_test.dart` | корректность статистики |
| `migration_test.dart` | миграция базы версии 1, сохранение после перезапуска |
| `performance_test.dart` | объём данных, планы запросов с индексами и без |
| `state_test.dart` | Cubit: пагинация, поиск, текущий пользователь |
| `widget_test.dart` | экраны и формы |

Откат транзакции проверяется несуществующим автором: задача уже вставлена,
запись истории падает на внешнем ключе, и задача должна исчезнуть.

## Ограничения

- На iOS приложение не собиралось и не запускалось: на Windows это невозможно.
- Проверено на эмуляторе Android (x86_64). На физическом телефоне не запускалось.
- Вложение можно прикрепить и удалить, открытие файла из приложения не сделано:
  в задании его нет.
- `build/app/outputs/flutter-apk/app-release.apk` собран только для эмулятора
  x86_64. Для телефона выполните `flutter build apk --release`.
